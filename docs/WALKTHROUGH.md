# Four-minute walkthrough plan

The organizer requires a 3–5 minute video showing the prototype working. Target four minutes. Record the actual application, not only slides. This document is a recording plan; no video has been produced yet.

## Before recording

- Open the public Cloudflare demo in a fresh incognito session with no leftover dependency edits.
- Keep the original 12-task plan for the seven-downstream-impact example.
- Prepare a change with most review actions already completed for the later portion; explicitly say those reviews were prepared earlier. Do not imply that skipped work completed automatically.
- Avoid displaying real account emails where unnecessary.
- Test site and recording audio, close unrelated tabs and disable desktop notifications.
- Ensure the final video link is accessible to judges.

## Timed sequence

| Time | Show | Explain |
| --- | --- | --- |
| 0:00–0:25 | Project overview | A drawing change can leave several people working from outdated assumptions. SiteSync connects ownership, dependencies and decisions. |
| 0:25–0:55 | Stakeholders and dependency map | Five stakeholder roles own different parts of the renovation. Relationships are mapped explicitly. |
| 0:55–1:45 | Bathroom change and impact panel | Show seven downstream tasks, explain a plumbing or procurement dependency path, and confirm the review plan. |
| 1:45–2:40 | Prepared reviews and one new review note | Show who is responsible and record what was checked. Explain that the other reviews were prepared earlier to keep the video concise. |
| 2:40–3:20 | Client approval and task statuses | Approve after all reviews. Change holds release, but unfinished task prerequisites still block dependent work. |
| 3:20–3:45 | Project memory and role restrictions | Show the review/approval trail. Explain that the public demo simulates stakeholders through a role switcher; actual team sign-in is disabled. |
| 3:45–4:00 | Wrap-up | Explicit dependencies and review evidence make coordination explainable. Next steps include drawing links, live updates and practical field evaluation. |

## Final check

Keep the recording between 3 and 5 minutes. Use a readable browser scale and verify playback with sound. Add the video URL to the repository README and submit it under the walkthrough item. The 30-minute remote presentation is separate; confirm its Q&A arrangement with the organizers.
